# Блиц-опрос (Blitz Quiz)

Учебное приложение «преподаватель — студенты» без серверного кода:

- **Интерфейс** — статические HTML/JS-страницы, публикуются на **GitHub Pages**.
- **Обмен данными** — JSON-файлы на вашем сервере **http://194.87.103.77/blitz** через обычный nginx:
  чтение — `GET`, запись — `PUT` (простые WebDAV-возможности nginx), списки файлов — `autoindex`.

## Правила теста

1. Преподаватель **не пишет вопрос** — он выбирает только **тип** раунда:
   - «варианты» А, Б, С, Д, Е — на ответ **20 секунд**;
   - «текст» — на ответ **40 секунд**.
2. У каждого студента свой **обратный отсчёт**, который стартует, когда студент *увидел* вопрос.
   Точная синхронизация часов не нужна: учитывается **время, которое каждый затратил** на ответ.
3. Ответы студентов приходят преподавателю и **группируются** (по варианту или по тексту);
   преподаватель отмечает **один правильный**: верно → +1 к «верным», остальные → +1 к «неправильным».
4. Итоговый **балл = 70% за верные ответы + 30% за скорость** (меньше суммарное время — лучше).
   Пропущенный раунд добавляет ко времени штраф (длительность раунда + 5 с), поэтому «молчать» невыгодно.
5. Группы по месту в рейтинге: **50% лучших — «отлично», следующие 30% — «хорошо», последние 20% — «удовлетворительно»**.
6. Заходить можно **в любой момент, в том числе посреди теста** — студент увидит вопрос и оставшееся время.

## Структура файлов

```
blitz-quiz/
├── index.html          — вход (выбор роли)
├── teacher.html        — панель преподавателя
├── student.html        — страница студента
├── css/style.css       — оформление
├── js/common.js        — обмен с nginx, серверное время, утилиты  (здесь настраивается API_BASE)
├── js/teacher.js       — логика преподавателя
├── js/student.js       — логика студента
├── nginx/blitz.conf    — готовые настройки nginx для 194.87.103.77
└── .nojekyll           — чтобы GitHub Pages не обрабатывал файлы Jekyll
```

Данные на сервере (создаются автоматически):

```
/var/www/blitz/data/
├── rooms/{КОД}.json              — состояние комнаты (текущий раунд, тип, время старта)
├── students/{КОД}/{sid}.json     — зарегистрированные студенты
├── answers/{КОД}/r{N}_{sid}.json — ответы (N — номер раунда)
└── results/{КОД}.json            — накопленные баллы и итоговые группы
```

## Шаг 1. Настройки сервера 194.87.103.77 (nginx)

### 1.1. Проверить наличие модуля WebDAV

```bash
nginx -V 2>&1 | tr ' ' '\n' | grep dav
```

Должно быть `--with-http_dav_module`. В Ubuntu/Debian он есть в пакетах `nginx-full` и `nginx-core`.
Если строки нет: `sudo apt install nginx-full`.

### 1.2. Создать каталог данных и отдать его nginx

```bash
sudo mkdir -p /var/www/blitz/data
sudo chown -R www-data:www-data /var/www/blitz
```

(`www-data` — пользователь рабочих процессов nginx; проверьте своим: `ps aux | grep nginx`.)

### 1.3. Установить конфиг

Скопируйте `nginx/blitz.conf` из этого архива:

```bash
sudo cp blitz.conf /etc/nginx/conf.d/blitz.conf
sudo nginx -t && sudo systemctl reload nginx
sudo ufw allow 80/tcp   # если включён брандмауэр ufw
```

Если на сервере уже есть свой `server{}` для 194.87.103.77 — не добавляйте второй `server`,
а перенесите два блока `location` (из `blitz.conf`) внутрь существующего.

### 1.4. Что делает конфиг (кратко — какие настройки нужны)

| Настройка | Зачем |
|---|---|
| `location /blitz/` + `root /var/www` | путь обмена http://194.87.103.77/blitz → каталог /var/www/blitz |
| `dav_methods PUT DELETE MKCOL;` | браузер сам записывает JSON-файлы (PUT) — серверный код не нужен |
| `create_full_put_path on;` | nginx сам создаёт недостающие подкаталоги (rooms/, answers/…) |
| `dav_access user:rw group:rw all:r;` | права 664 на записанные файлы |
| `autoindex on;` | GET каталога отдаёт список файлов — учитель опрашивает ответы студентов |
| `add_header Access-Control-Allow-Origin "*"` (+ Methods/Headers) | CORS: страница с GitHub Pages может обращаться к серверу |
| `if ($request_method = OPTIONS) { return 204; … }` | ответ на CORS-preflight |
| `Access-Control-Expose-Headers "Date, …"` | JS читает заголовок Date — определение смещения часов |
| `add_header Cache-Control "no-store" always;` | браузер не кэширует состояние/ответы |
| `client_max_body_size 2m;` | защита от крупных загрузок |

(Необязательно) защита записи паролем для `rooms/` и `results/` — закомментированный блок
в конце `blitz.conf`; пароль затем указывается в поле «Пароль учителя» на странице преподавателя:

```bash
sudo htpasswd -bc /etc/nginx/blitz.htpasswd teacher ПАРОЛЬ
```

### 1.5. Проверка

```bash
curl -X PUT -H 'Content-Type: application/json' -d '{"test":1}' http://194.87.103.77/blitz/data/test/ping.json
curl http://194.87.103.77/blitz/data/test/          # autoindex: должен показать ping.json
curl -X DELETE http://194.87.103.77/blitz/data/test/ping.json
```

## Шаг 2. Публикация на GitHub Pages

1. Создайте репозиторий на GitHub (например, `blitz-quiz`).
2. Загрузите **все файлы, кроме папки `nginx/`** (index.html, teacher.html, student.html, css/, js/, .nojekyll) в корень ветки `main`.
3. Откройте **Settings → Pages → Build and deployment → Source: Deploy from a branch**, Branch: `main` / `(root)` → Save.
4. **ВАЖНО.** В **Settings → Pages** НЕ включайте **Enforce HTTPS**.
   Страницу открывайте по адресу вида:
   `http://ВАШ_ЛОГИН.github.io/blitz-quiz/`
   Иначе браузер заблокирует обращение к `http://194.87.103.77/blitz` как mixed content
   (HTTPS-страница не может делать запросы к HTTP-серверу).
5. Если сервер уже доступен по HTTPS (сертификат) — поменяйте в `js/common.js`
   строку `API_BASE` на `https://…`, включите Enforce HTTPS и пользуйтесь HTTPS-версией.

Адреса страниц:

- преподаватель: `http://ВАШ_ЛОГИН.github.io/blitz-quiz/teacher.html`
- студенты: `http://ВАШ_ЛОГИН.github.io/blitz-quiz/student.html` (можно с кодом: `student.html#КОД`)

Ссылку с кодом комнаты удобнее давать студентам прямо из панели преподавателя (кнопка «Копировать»).

## Как пользоваться

**Преподаватель:** открыть `teacher.html` → «Открыть комнату» (код создаётся автоматически) →
дать студентам ссылку/код → кнопкой запустить раунд «Варианты (20 с)» или «Текст (40 с)» →
следить за ответами по таймеру → нажать «Это правильный ответ» у нужной группы →
«Следующий раунд» или «Завершить тест» (таблица с баллами и группами, выгрузка CSV).

**Студент:** открыть `student.html` (или ссылку с кодом) → ввести код и имя →
ждать вопроса → ответить до конца отсчёта. Можно зайти посреди теста.

## Неисправности

| Симптом | Причина / решение |
|---|---|
| `nginx -t`: unknown directive "dav_methods" | нет модуля http_dav_module → `sudo apt install nginx-full` |
| 403 Forbidden при GET каталога | права: `chown -R www-data:www-data /var/www/blitz` |
| PUT возвращает 405 | модуль dav не подключён (см. выше) |
| 409 Conflict при PUT | не включён `create_full_put_path on;` или нет прав на каталог |
| В консоли браузера ошибка CORS | не добавлены заголовки `Access-Control-*` (проверьте конфиг, `nginx -t && systemctl reload nginx`) |
| Запросы блокируются, ошибка mixed content | страница открыта по https, а сервер по http → откройте по `http://…github.io/…` и не включайте Enforce HTTPS |
| «Нет связи с сервером» | недоступен 194.87.103.77:80 (проверьте `curl` из шага 1.5, брандмауэр) |
| Данные накапливаются | удалите старое: `rm -rf /var/www/blitz/data/answers/{КОД}` и т.п. |

## Ограничения

Защита данных минимальна: любой, кто знает адрес, может читать и писать JSON
(для учебного сценария это допустимо). Для ограничения записи используйте
блок basic auth в `nginx/blitz.conf`. Храните только имена студентов — персональные
данные в этой схеме публиковать не следует.
